# 100편 장면 다시 그리기 설계

## 의도

지금 화면들은 "대충 찍어낸 것처럼 인위적"이다. 같은 `barn()` 함수가 네 장면에 똑같이 나오고, 나무와 바위가 같은 규칙으로 줄지어 찍히고, 면은 단색, 판자와 가지는 같은 간격으로 반복된다. 이 작업의 목표는 장면마다 직접 다시 그려서 **어느 두 장면에도 같은 모양의 집이나 나무가 없게** 하는 것이다. 품질이 작업량보다 우선이다.

## 목표

- 장면 속 모든 건물, 나무, 바위, 울타리, 풀 같은 사물을 장면별로 새로 설계해서 그린다. 모양 자체를 바꿔도 된다.
- 실내(가구·주전자·턴테이블 등), 거리(정류장·자판기·옥상 등), 하늘(모래언덕·협곡·능선 등) 계열도 같은 기준이다: 가벼운 손질이 아니라 사물마다 새로 설계한다.
- 구도도 바꿔도 된다: 지평선 높이, 주인공 위치, 카메라 각도를 장면마다 새로 잡을 수 있다. 단, 장면 제목과 환경음이 설명하는 내용과 어긋나지 않아야 한다.
- 같은 장면 안에서도 같은 사물은 하나도 똑같지 않다: 나무마다 줄기 기울기, 가지 갈래, 잎 덩어리가 다르다.
- 스타일: **가까운 사물은 재질과 입체감**(시안 A — 판자 한 장씩 다른 색, 빗물 자국, 처마 그림자, 기초, 이끼, 창틀과 창턱), **먼 배경은 빛과 실루엣**(시안 C — 안개, 멀수록 옅어짐, 가장자리 림 라이트). 기준 이미지: `review/style-house-A.jpg`, `review/style-house-C.jpg`.
- 지금까지 만든 것은 유지한다: 공용 마감 처리(블룸·그레인·비네트), 장면별 조명 표, 24초 무한 반복, 환경음.

## 하지 않을 것

- 움직임 작업(바람에 흔들림, 연기 등)은 이 작업 뒤에 따로 한다. 다만 다시 그릴 때 나중에 흔들 수 있는 단위(나무 한 그루, 가지 덩어리)로 나눠 그린다.
- 장면의 주제와 제목, 소리는 바꾸지 않는다(구도는 바꿔도 된다).
- 10번(불꽃놀이)은 하늘과 물이 전부여서 대상에서 뺀다.

## 실패로 보는 경우

- 장면은 바뀌었는데 두 장면을 나란히 놓으면 같은 나무나 같은 집이 보인다.
- 디테일이 늘었지만 장면이 다시 "규칙적으로 찍힌" 느낌이다: 같은 간격, 같은 각도, 좌우 대칭.
- 재생이 끊긴다(한 프레임 33 ms 초과) 또는 24초 반복 이음매가 보인다.
- 장면 사이 품질이 들쭉날쭉하다.

## 제약

- Canvas 2D, 1920×1080, `createScene(makeCanvas)`가 `painter(ctx, phase)`를 돌려주는 구조는 그대로.
- 결정적이어야 한다: 장면별 시드 난수만 쓰고 `Math.random` 금지. 정지 화면과 재생 화면이 같아야 한다.
- 무거운 그리기는 장면 생성 때 한 번 판(plate)에 그려 두고, 프레임마다는 움직이는 것만 그린다.
- 정지 화면 100장(960×540)과 미리보기 HTML을 다시 만든다.
- 성능 기준은 미리보기 플레이어(`web/player.js`)를 브라우저에서 돌릴 때다. 프레임당 33 ms 이하(지금까지 감사와 같은 방식: 12프레임 평균). 장면 생성(판 그리기)은 장면 전환이 답답하지 않도록 1초 이내를 목표로 한다. (작성자 판단)
- 출발점은 현재 작업 트리다. 공용 모듈, 마감 처리, 100편 조명 표는 이 세션에서 끝낸 작업이고(일부 미커밋), 그 위에 쌓는다.

## 진행 방식 (검토한 안)

1. **공용 사물 라이브러리** — 집·나무 함수를 하나씩 만들어 장면이 호출. 품질을 한 곳에서 올리기 쉽지만, 결국 같은 함수의 변형이라 "찍어낸 느낌"이 남을 수 있다.
2. **장면마다 직접 다시 그리기 (선택됨)** — 장면별로 사물의 형태를 따로 설계한다. 가장 손이 많이 가지만 장면마다 개성이 가장 강하다. 사용자가 이 방식을 골랐다: "장면마다 직접 다시 그리되 같은 모양의 나무가 없을 정도로 장면마다 색다름을 추구".
3. **기존 함수 다듬기** — 가장 빠르지만 모양이 그대로라 근본 해결이 안 된다.

## 정해진 방법

- **형태는 장면마다 따로.** 각 장면 파일(또는 장면 함수)이 자기 사물의 형태를 직접 정한다. 예: 43번 자작나무와 55번 대숲과 90번 사과나무는 서로 다른 코드로 그린다.
- **낮은 수준의 도구는 공용으로 둔다 (제안, 작성자 판단).** 노이즈, 흔들리는 윤곽선, 나무껍질·판자·돌 질감을 칠하는 붓, 조명 맵 같은 "그리는 도구"는 `lib/paint.cjs`에 둔다. 도구가 같아도 형태가 장면마다 다르면 찍어낸 느낌은 나지 않는다. 이 선을 넘는 공용 함수(예: `tree()` 하나로 모든 나무)는 만들지 않는다.
- **장면 안 변화.** 같은 종류 사물을 여러 개 그릴 때는 개체마다 크기·기울기·구조를 시드로 바꾸고, 배치는 격자나 등간격을 피한다(뭉침과 빈 곳이 있게).
- **깊이.** 가까운 층은 질감과 디테일, 먼 층은 안개 색으로 섞이고 윤곽만 남긴다(공용 `aerial`).
- **빛.** 장면의 광원(달, 새벽 지평선, 창, 등) 방향에 맞춰 사물의 밝은 면과 그림자 면을 정한다. 조명 표는 새 형태에 맞게 다시 맞춘다.

## 순서

1. **시범 3편**: 96(농가, 눈), 43(자작나무 숲길), 33(보트 창고, 물가). 집·나무·물가를 하나씩 대표한다. 여기서 멈추고 사용자 확인을 받는다. 확인 전에는 나머지로 넘어가지 않으며, 수정 요청이 오면 시범 3편을 고쳐 다시 보여준다.
2. 계열별로 진행: 날씨(86–100) → 숲(41–55) → 물가(26–40) → 실내(11–25) → 거리(71–85) → 하늘(56–70) → 원본 9편(01–09).
3. 계열마다 끝나면 전후 비교 이미지, 오류·반복 이음매·프레임 시간 점검, 정지 화면 갱신.

## 작업자에게 맡기는 것

- 각 장면 사물의 구체적인 형태와 수, 배치.
- 공용 도구에 무엇을 둘지의 세부(위 원칙 안에서).
- 장면별 조명 표 수치 조정.
